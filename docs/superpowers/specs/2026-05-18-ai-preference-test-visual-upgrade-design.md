# AI 使用偏好测试视觉升级设计

## 目标

在不推翻当前 TypeScript、评分、题库、海报下载和测试基座的前提下，把页面从“可用问卷”升级为更有产品感、分享感的测试体验。重点解决第一屏平淡、测试仪式感弱、结果页缺少记忆点的问题。

## 范围

- 背景改为浅蓝科技感基调。
- 增加全屏动态粒子 canvas：粒子缓慢漂浮、相近粒子连线，作为装饰背景，不影响答题和可访问性。
- 首页升级为 hero 布局：强标题、价值描述、测试元信息、维度预览和开始测试按钮。
- 测试页保持 16 题和 4 选项评分逻辑，提升卡片层次、进度条和选项状态。
- 结果页强化类型卡片、维度信息、主副身份、建议区和图片下载入口。
- 保留本地运行、局域网分享、PNG 结果图下载。

## 非目标

- 不把题型改为 5 档量表。
- 不修改评分算法、题库权重和人格文案。
- 不加入后端、账号、统计或远程存储。
- 不引入外部图片或第三方动画库。

## 结构设计

- `src/app.ts` 继续负责 DOM 渲染和交互。
- 新增 `src/particles.ts`，只负责 canvas 粒子背景初始化、resize 和动画循环。
- `src/main.ts` 在创建应用前初始化粒子背景。
- `src/styles.css` 承担浅蓝视觉系统、hero、测试卡片、结果页和 canvas 层级。
- 测试继续用 jsdom 覆盖 DOM 结构；粒子模块通过 mock canvas context 和 requestAnimationFrame 做轻量行为测试。

## 交互与视觉

首页第一屏应直接传达“AI / Agent 使用偏好测试”的主题，浅蓝背景上有动态粒子连接。内容区采用左右布局：左侧是标题和 CTA，右侧是四个维度预览。移动端改为单列。

答题页保留当前“每题四选一”的低摩擦体验，但选项使用更明显的 hover/selected 状态，进度条有更强的完成感。

结果页保留海报和详情双列布局，但强化类型码、人格称号、主副身份和建议卡片，让用户截图或下载结果图时更有分享动机。

## 可访问性与性能

- canvas 设置 `aria-hidden="true"`。
- `prefers-reduced-motion: reduce` 时只绘制静态粒子，不持续动画。
- canvas 固定在背景层，不遮挡点击。
- 不依赖网络资源。

## 验证

- 新增/更新测试覆盖：
  - 页面渲染粒子 canvas。
  - 首页包含维度预览和更强产品文案。
  - 结果页仍包含主副身份、维度、建议、下载入口。
  - 粒子初始化能创建 canvas context、响应尺寸、触发绘制。
- 运行完整测试、类型检查、生产构建。
- 用浏览器检查首页、答题页、结果页在桌面和移动宽度下不重叠，浅蓝动态粒子背景可见。
